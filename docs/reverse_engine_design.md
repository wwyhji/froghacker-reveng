## 0. 核心主张

**逆向不是「找字符串」，是「追踪业务逻辑的关联链」。**

key 的完整生命周期是一条链：

```
key 生成（硬编码/派生） → 存储（.rodata/全局/JS常量） → 使用（加密函数参数） → 作用于（加密数据）
```

这条链是有向图，不是模式匹配。所以引擎的主体是**游标在关联图上导航**，弱模型工蚁只做局部判断，判断的对错由确定性验证裁决。

**弱模型全程不是「裁判」，是「加速器」**——它负责把候选空间快速缩小，对错交给可验证性。

---

## 1. 节点类型（关联图的顶点，5 类）

| 节点 | 含义 | 例 |
|------|------|-----|
| `DATA` | 加密数据文件 | tdata / jsc / 账目缓存 |
| `FUNC` | 函数 | AES_encrypt / 派生函数 |
| `VAR` | key 的载体（变量/字段） | 全局变量 / SO 里的 std::string |
| `CONST` | 硬编码常量 | `f192bac7-2d86-41` |
| `EXT` | 外部输入（不可静态定位的终点） | 网络 / 设备串 / 时间戳 |

---

## 2. 关联边类型表（游标能跳的 5 个方向）

这是引擎地基。每类边 = 一个追踪方向 + 一个工蚁动作。

| # | 边 | 方向 | 语义 | 工蚁读哪个工具 | 工蚁产出 |
|---|-----|------|------|---------------|---------|
| 1 | `ENCRYPTED_BY` | DATA → FUNC | 这数据被哪个函数加密 | 文件头 magic / 已知格式规则 | 加密算法（AES/XXTEA/异或/无） |
| 2 | `KEY_ARG` | FUNC → VAR | 加密函数的 key 参数是哪个变量 | jadx 反编译 / capstone disasm 调用点 | key 参数的「来源类别」 |
| 3 | `SOURCE` | VAR → CONST\|FUNC\|EXT | 变量的值从哪来 | capstone 赋值指令 / `_read_keyvar` / strings | 来源三分类 |
| 4 | `CALLED_BY` | FUNC → FUNC | 谁调用了它（定位传参） | jadx xref / capstone BL 指令扫描 | 调用点 + 实参 |
| 5 | `STORE` | VAR → 内存段 | 值存在 .rodata/.data/JS 常量 | readelf/objdump / grep JS | 存储位置确认 |

**回溯主链**（游标默认走这条，`CALLED_BY`/`STORE` 是辅助边，主链模糊时旁证）：

```
DATA ──①ENCRYPTED_BY──▶ FUNC ──②KEY_ARG──▶ VAR ──③SOURCE──▶ CONST ✅ 收敛（key 到手）
                                                        └─▶ FUNC(派生) ──③SOURCE──▶ EXT ❌ 死路（动态 key）
```

## 3. 游标状态机

```
状态 = (节点, 待答问题)
转移 = 工蚁四选一结果 → 沿对应边跳
单调性 = 节点分析完打 covered，游标只跳「未 covered + 信息素≥0」的边
```

```
S0 (DATA)   问「被什么加密」           →①→ S1
S1 (FUNC)   问「key 参数来源类别」      →②→ S2
S2 (VAR)    问「值从哪来」             →③→ S3a(CONST) 收敛✅
                                       →③→ S3b(FUNC派生) 继续回溯
S3b(FUNC)   问「派生算法+输入」         →③→ S4
S4 (EXT)    终止：key 不可静态定位 ❌
```

每个状态的「待答问题」固定，工蚁不需要理解全局，只回答游标指到的那个问题。

## 4. 想法片 schema（上下文管理）

逆向节点 = 想法片，四项铁律（原子化/可链接/按需加载/渐进披露）全部落地：

```yaml
---
name: rev-node-548330            # 唯一标识
kind: VAR                        # DATA|FUNC|VAR|CONST|EXT
status: pending|analyzed|dead_end|uncertain  # 单调覆盖标记
edges_in:  [rev-node-aes]        # SOURCE 上游
edges_out: [rev-node-const-f19]  # 候选下游
info_pheromone: +1               # 信息素方向位（通/不通）
---
# 正文 = 工蚁唯一要读的东西
question: "值从哪来"
tool_output: "<capstone 反汇编片段>"
four_choices: {A: 硬编码, B: 全局变量, C: 派生返回, D: 无法确定}
ant_answer: "A"
evidence: "0x5482f4 赋值立即数"
```

**游标 = 只留索引，不留正文**：

```
cursor:
  chain:   [rev-node-tdata, rev-node-aes, rev-node-548330]   # 只存 name
  current: rev-node-548330
  covered: [rev-node-tdata, rev-node-aes]                     # 单调性依据
```

**工蚁上下文 = 三个想法片封顶**：
1. 当前节点想法片（完整正文 + tool_output + four_choices）
2. 上游节点索引（一行摘要）
3. 四选一题目

不装：链上其他节点正文、其他工蚁历史、工具全量历史。**工蚁上下文大小与链长度解耦**。

## 5. 四选一判断模板（工蚁的可靠边界）

每个状态配套四选一，工蚁输出**选项字母 + 一句话理由**，不做开放生成。

**S0 — 「被什么加密」**
```
工具输出：tdata 文件头 hex
A) AES（分组加密，16 字节块）  B) XXTEA（Cocos 标准）
C) 自定义异或/混淆            D) 未加密（明文/压缩）
```

**S1 — 「key 参数来源类别」**
```
工具输出：AES_encrypt(buf, key) 反汇编/反编译片段
A) 立即数常量   B) 全局变量（.data/.rodata/.bss）
C) 函数返回值   D) 外部输入（网络/文件/运行时）
```

**S2 — 「值从哪来」**
```
工具输出：变量赋值指令 + 交叉引用
A) 硬编码常量   B) 派生函数返回（md5/hash/拼接）
C) 运行时外部输入  D) 无法确定（触发 CCM 求助）
```

**S3b — 「派生算法 + 输入」**
```
工具输出：派生函数反汇编
A) 标准哈希（md5/sha，输入常量）  B) 拼接/截取（常量+时间戳）
C) 随机/设备相关（不可复现）      D) 无法确定
```

**收敛判据**：S2 选 A（硬编码）→ 读 `STORE` 边确认存储 → 拿到 key 字节 → **链闭合**。

## 6. 准确率四层兜底

核心原则：**模型给「候选方向」，确定性给「最终裁决」，准确率不靠模型，靠可验证性。**

```
① 降维+冗余    工蚁四选一多投票（默认1，低置信升3）    —— 降低错误率
② 微观验证+回溯 逐节点读字节/反汇编裁决，错则回溯       —— 检测局部错误
③ 终局闭环      错误key解不出明文（数学事实）           —— 漏网必暴露
④ 诚实降级      穷尽不定→输出证据链，不猜               —— 天花板自守
```

### ① 降维+冗余
四选一（分类）比开放生成错误率低一个量级。同一节点派 N 个工蚁独立作答，3 票一致前进，票数分散触发②或 CCM 求助。

### ② 微观验证 + 回溯
每个四选一答案后挂确定性验证，答错立刻抓出，抓出就回溯：

| 四选一 | 模型答 | 确定性验证（不靠模型） |
|--------|--------|----------------------|
| S0 加密方式 | AES | XXTEA 解 jsc → 看是否出 `1f 8b` gzip 魔数 |
| S1 key 来源 | 全局变量 | capstone 看 key 参数从哪条加载指令来 |
| S2 值来源 | 硬编码 | 读该地址字节 → 是不是可读字符串 |
| S3b 派生算法 | md5 | 反汇编找 `0x67452301` md5 魔数常量 |

节点三态：`pending / analyzed(验证通过) / verified_false(排除)`。回溯回最近分叉点走未试边。**本质是 DFS + 确定性剪枝，剪枝依据是验证结果不是模型置信度。**

### ③ 终局闭环
最终 key 解密 tdata/jsc，解出有效明文（JSON/UTF-8中文/gzip魔数/可读字符串）= 对；解不出 = 错。**错误的 key 解不出有效明文是数学事实，所以漏网错误最终必然暴露。** 准确率的最终锚点不落在任何模型判断上。

### ④ 诚实降级
弱模型答不对 + 验证无法唯一裁决 + 回溯穷尽 → 不猜，输出完整证据链（已排除边 + 排除依据 + 卡点），结论 `{状态: 无法静态定位, 建议: 人工/动态分析}`。「这个 key 是动态派生的」本身是有价值的确定结论——它排除了硬编码路径。

**隔离场景自足性**：四层全部离线可用（弱模型本地跑、验证纯工具、解密闭环是数学事实）。无一层依赖强模型或网络。

## 8. 数据可达性边界

「AI 端纯本地」只约束 AI 推理，不约束工具/网络。但**隔离场景（完全不能联网）**下有一类硬边界：若目标数据物理存储在云端、本地不可达，则**只能标「数据不可达」，不是「解不出」**。

这是数据可达性问题，不是准确率问题。隔离场景下诚实结论 = 数据不可达，不猜内容。

## 8.5 动态降级（静态死路 → 内存 dump）

诚实降级（§6④）不是终点。当静态追踪走到死路（key 在加固壳 / native 混淆），还有一条动态路径。

### 8.5.1 核心思路

**无论 key 藏多深、算法多复杂，目标运行时必然把加密数据解密成明文，明文就在内存里。** 直接 dump 内存搜明文/key，跳过「找 key → 理解算法」整段。

### 8.5.2 关联图扩展

新增节点：`MEM`（内存数据）

新增边（动态边）：

| # | 边 | 方向 | 语义 | 工蚁动作 |
|---|-----|------|------|---------|
| 6 | `STATIC_DEAD_END` | VAR/FUNC → dead_end | 静态不可达（key 在壳 / native 混淆） | 标记 uncertain，输出证据链 |
| 7 | `DUMP` | dead_end → MEM | 动态降级，dump 内存 | 调度 `dump_memory` 工具 |
| 8 | `CONTAINS` | MEM → CONST\|明文 | 内存里提取 key/明文 | 四选一判断 |

### 8.5.3 状态机扩展

```
S2 (VAR) 问「值从哪来」 → 静态走死路（SOURCE 边断）
   ↓ 诚实降级：标记 uncertain，输出证据链（不是终点）
   ↓ 触发动态降级
S5 (MEM) 问「dump 出的数据是什么」 → dump_memory → 工蚁四选一
   ↓ CONTAINS 边
S6 (CONST/明文) → 拿到 key 或明文 → 回到静态（解密 tdata）→ 终局闭环 ✅
```

### 8.5.4 dump 工具节点

`dump_memory(pid)` —— 引擎工具链新增，复用 dexripper 非注入逻辑：

1. 解析 `/proc/pid/maps` 枚举内存段
2. 读 `/proc/pid/mem`（**非注入、不 hook，绕加固壳反 frida**）
3. 搜索目标：明文特征（中文/JSON）+ key 特征（16/24/32 字节形态）

**关键**：dump 是引擎调度的工具，不是人工操作。游标走到死路 → 调度 `dump_memory` → 工蚁判断结果。

### 8.5.5 工蚁四选一（dump 结果判断）

S5（MEM 节点）：「这段 dump 数据，像什么？」

```
A) 聊天明文（中文/JSON/可读文本）
B) AES key（16/24/32 字节 key 形态）
C) 加密数据（密文，需继续找 key）
D) 无关数据（跳过这段）
```

### 8.5.6 与诚实降级的关系（闭环）

```
静态追踪 → 死路 → 诚实降级（uncertain + 证据链）   ← 静态路径终点
                    ↓ 不是终点
                  动态降级（dump）                   ← 动态路径起点
                    ↓ 拿到 key/明文 → 回到静态闭环 ✅
                    ↓ 拿不到 → 真正终止（数据不可达 / 需更深动态分析）
```

**诚实降级是「静态的终点」，动态降级是「动态的起点」——两者接起来，引擎才有完整闭环。** 静态追踪到加固壳死路时，即触发动态降级。

## 11. 落地顺序（实现时的建议）

```
① 逆向想法片 schema + 游标状态机（纯数据，无 AI）     —— 先跑通关联图建模
② 确定性静态管线（解包/提取/扫候选/解密，无 AI）      —— jadx/androguard/capstone 静态工具链
③ 动态降级工具（dump_memory，dexripper 非注入）       —— 静态死路 → 内存 dump（§8.5）
④ 四选一 + Ollama 工蚁（弱模型接局部判断）            —— 最小 AI 介入
⑤ 准确率四层兜底（验证/回溯/终局/降级）    —— 最后加保险
```

每步独立验证。② 静态追踪管线已跑通；③ 待环境（root Android）。
